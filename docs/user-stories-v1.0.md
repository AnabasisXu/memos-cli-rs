# memos-cli 用户故事（User Stories）

- 版本: 1.0
- 日期: 2026-09-20
- 目的: 供人审阅"这是不是我想要的东西"，是最初的许愿场景；每个故事在 `user-manual-v2.0.md` 中均有对应可复现操作

## 角色

- **笔记用户**：用 memos 记录日常，想要快速、不打断思路地存取
- **效率用户**：信息量大，需要筛选、批量整理、脚本化工作流
- **备份者**：需要可靠的全量导出与迁移
- **AI Agent**：需要一个无浏览器依赖、可脚本调用的接口

---

## 故事 1：三秒记录灵感

> 作为笔记用户，我想要在终端里不打标签、不填表单地记下一条灵感，以便想法出现时立刻捕捉、不切换上下文。

- 操作：`memos-cli + 想法内容`，返回 `created <uid>`
- 成功标志：立即出现在列表，Web 端同步可见
- 验收位置：手册 §3.4

## 故事 2：只看我关心的

> 作为效率用户，我想要用 taskwarrior 一样的语法筛选笔记（含标签、排除标签、正文正则），以便从几百条笔记里快速定位工作相关的内容。

- 操作：`memos-cli l +work`、`memos-cli l -test`、`memos-cli l /deadline/`，可组合 `+work /urgent/ -test`
- 成功标志：筛选结果为 AND 语义；省略 `list` 直接 `memos-cli +work` 也生效
- 验收位置：手册 §3.6

## 故事 3：列表编号直接操作

> 作为效率用户，我想要在列表里看到的编号直接用于查看、编辑、删除，以便不用复制粘贴 uid。

- 操作：`memos-cli l` 后 `get 3` / `e 3` / `- 3`
- 成功标志：编号映射到当次列表的对应 memo
- 验收位置：手册 §3.1 / §3.2 / §3.5

## 故事 4：批量清理

> 作为效率用户，我想要一次删除多条（单项、范围、逗号列表），且删除前有确认，以便安全地批量清理旧笔记。

- 操作：`memos-cli - 1 3-4 6`（逐条预览 + y/N 确认）；`-y` 跳过确认
- 成功标志：删除列表正确，误删有确认保护
- 验收位置：手册 §3.5

## 故事 5：全量备份

> 作为备份者，我想要一条命令导出所有笔记为 TSV，以便离线保存或迁移到另一台 memos（或导入其他工具）。

- 操作：`memos-cli export > all.tsv`
- 成功标志：覆盖分页后的全部笔记；内容内的换行/制表符被转义，TSV 结构不破坏；`import` 可无损还原
- 验收位置：手册 §3.7 / §3.8

## 故事 6：批量导入

> 作为备份者，我想要把导出的 TSV 重新导入（含容错：单条失败不中断），以便迁移或恢复。

- 操作：`memos-cli import < all.tsv`
- 成功标志：成功条目标记 `imported`，失败条目标记 `error` 且继续
- 验收位置：手册 §3.8

## 故事 7：不知道写哪条时搜索

> 作为笔记用户，我想要 TUI 里全量搜索并逐条翻看，以便快速回顾关键词相关的所有笔记。

- 操作：`memos-cli tui` → `/ 关键词` → `j/k` 导航 → `Enter` 编辑
- 成功标志：TUI 列出匹配项（每页 20 条），可翻页、选中、批量删除
- 验收位置：手册 §3.9

## 故事 8：别人给我一台新机器

> 作为任意用户，我想要在干净机器上用一条命令完成配置并立刻开始使用，以便迁移环境时不被配置文件折腾。

- 操作：`memos-cli config --base <url> --token <pat>` 后直接 `memos-cli l`
- 成功标志：配置写入 UTF-8 无 BOM + 0600；`config --show` 脱敏显示；token 错误时快速失败
- 验收位置：手册 §2 / §3.10

## 故事 9：Agent 代我记笔记

> 作为 AI Agent，我想要无浏览器、无交互依赖的命令行接口（stdout/stderr 结构化、退出码区分成败），以便在自动化流程里读写笔记。

- 操作：`memos-cli + done: task finished`、`memos-cli l /done/`、`memos-cli export`
- 成功标志：命令可脚本化链式调用；错误走 stderr、退出码非 0
- 验收位置：手册 §3.4 / §3.6 / §3.7

## 反模式提醒（避免的许愿）

- ❌ "重写一个 memos 客户端"——范围失控，隐含 Web UI/多实例/离线等非目标（见 PRD §6）
- ❌ "让数字编号永久稳定"——编号依赖当次拉取顺序，列表变化即变；由设计文档记录
- ❌ "筛选要扫正文里的 #tag"——当前 `+tag` 只匹配 API `tags` 字段，这是文档化约定，改动需另立需求
