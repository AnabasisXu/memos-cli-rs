| 变更 | 实现 |
|---|---|
| list 表头 | `Id Date Tag Description`（title case）；`--raw` 无表头 |

| 日期截断 | create_time 显示 `YYYY-MM-DD`（截前 10 字符，`short_date`） |

| add 主命令名 | `memos-cli add 正文 +tag`（TW `task add` 同款）；`+` 降为别名保留兼容；`+tag` 内部转写正文 `#tag`（usememos 渲染约束、免 `#` shell 注释引号） |

## 3. 第二轮待审用例

### T-r2-2 / T-r2-3 表头与对齐双模式

- 管道：`memos-cli li` 首行恰为 `Id Date Tag Description`（tab 分隔、无 ANSI）；`memos-cli ls` 为 `Id Tag Description`
- TTY：列对齐——`Date` 与 `Tag` 之间至少有 2 空格间距，全行数据列起始位置一致（修复用户反馈的错位；已确认符合预期）
- TSV 偏好：`memos-cli li > file.tsv` 文件内为 tab 分隔纯文本（无对齐空格、无 ANSI），可用 `cut -f 3` 等工具解析
- `memos-cli li --raw` 输出 JSON 无表头

### T-r2-4 日期精确到日

- list 数据行第 2 列 `^\d{4}-\d{2}-\d{2}$`（无 `T`、无时区）
- `--raw` 与 `export` 仍为完整 RFC3339（截断仅列表显示层）

### T-r2-5 / T-r2-6 完整信息展示

- `memos-cli <uid>` / `memos-cli <编号>` 输出四键值行（uid/date/tags/content）
- `memos-cli <uid> --raw` 仍 JSON
- 多行正文：content 行首行带前缀，后续行直接输出（文档化）

### T-r2-7 边界

- 空列表：仍打印表头；`memos-cli li -n 1`：表头 + 恰 1 数据行
- 无标签 `-`、多标签空格分隔
- `memos-cli li | head -1` 无 broken pipe panic
- `memos-cli --no-default`（无命令）≡ `memos-cli li --no-default`

### T-r2-8 回归（round 1 核心）

- 筛选全语法 AND、默认分派（无参/编号/uid/+tag/-tag/裸词/22字符uid）、`del /re/ -y`、`del 0` 报错、`tags`/`ids`、`help delete` 英文、import 幂等

### T-r2-9 add 语法（TW 同款）

- `memos-cli add another test +sometag` 无引号创建成功；正文为 `another test #sometag`（`+` 转写 `#`）
- API tags 字段含 `sometag`：`memos-cli li +sometag` 命中该条；`memos-cli ls +sometag`、`memos-cli tags` 计数含 sometag
- `memos-cli add 多词 正文 +tag1 +tag2` 多标签；`memos-cli add --tag work` 兼容
- `memos-cli + hello` 别名仍可用（v0.1 兼容）
- `memos-cli add`（空正文）读 stdin；`echo x | memos-cli add`
- shell 注释对照：`memos-cli add 备注 #tag` 实际只传 `备注`（shell 吞掉 `#` 后续）——文档化约束：写字面 `#` 需引号（与 TW 相同）
