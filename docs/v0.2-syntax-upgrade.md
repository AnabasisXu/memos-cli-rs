## Phase 1：help 基线修改（用户明确需求 + P0 审计项）

### P1-1 list 别名调整：删 `l`，新增 `li`

需求行：`list 列表（短命令 l / ls） [aliases: l, ls] --- 删除l，list拆分为li`

- `list` 子命令：删除别名 `l`，新增 `li`（`li` 是 list 的唯一前缀缩写，对齐 Taskwarrior 缩写表；`l` 是歧义前缀，TW 本不提供）
- **`ls` 保留并升级为独立短列表命令**（D1 定稿 2026-09-20）：从 list 的别名列表移出，语义对齐 TW `ls`（short listing）
  - 输出三列：`编号\t标签\t内容`——标签为 API `tags` 字段、空格分隔、无标签显示 `-`；内容截断 40
  - 支持与 list 相同的筛选、`-n`/`--page-size`、`--raw`（全局）；不设 `-f/--full`（短列表不含时间列）
  - 实现：`Commands::Ls` 独立变体（参数：`limit`、`page_size`、`filters`），复用 cmd_list 渲染逻辑走 `short=true` 分支
- 冲突检查：`li`/`ls` 均不与现存/新增命令前缀重叠（edit/e、+/−、export/import、tui、config/cfg、version、help、tags、ids）；P1-2 白名单加入 `ls`

### P1-2 删除 `get` 命令，改为默认命令智能分派

需求行：`get 查看正文 [aliases: show, cat] -- 删除这个功能，默认支持筛选`

**设计**：删除 `Get`/`show`/`cat` 命令变体。`run()` 的预处理重写逻辑（现已有 `+tag`/`/regex/` 首参 → `list`）扩展为默认命令分派：

| 首参形态 | 分派 | 说明 |
|---|---|---|
| （无参数） | `list` | TW `task` ≡ `task list` |
| 单个编号或 uid（`3` / `u5` / `memos/u5`） | 查看全文（原 `get` 逻辑） | TW `task 28` 隐含默认报表 |
| `+tag` / `-tag` / `/regex/` / 裸词 / `time.after:` 等筛选 | `list` + 筛选 | bash 风格推广（现仅支持 `+tag`、`/regex/`） |
| 已知子命令名 / 已知顶层 flag | 不重写 | 白名单见下 |

- 白名单（首参命中则不重写）：子命令 `list li ls edit e + - del delete rm tags ids export import tui config cfg version help`；顶层 flag `-h -V --help --version --base --token --raw`（`-h`/`-V` 必须排除，否则 `memos-cli -h` 会被错误重写为 `list -h`）
- `--raw` 从 list/get 子命令提升为**顶层全局 flag**（`global = true`），`memos-cli 3 --raw` 可用；list/get（现默认分派）各自 `--raw` 移除
- `resolve_id` 保留（`edit` 仍用）；`cmd_get` 逻辑改为内部 `cmd_show(uid, raw)` 供默认分派调用
- 多参数数字 `memos-cli 3 4` **[待确认 D2]**：推荐按裸词筛选处理（content contains "3" and contains "4"，与 `list` 一致）；不推荐报错
- 已知局限：显式 `memos-cli l 3` 是"正文含 3"的筛选，隐式 `memos-cli 3` 是"查看编号 3 全文"——命令结构差异，文档化

### P1-3 version 输出添加编译时间

需求行：`version 打印版本（同 --version）--添加编译时间`

- 新增 `build.rs`：注入 `cargo:rustc-env=BUILD_TIME=<UTC ISO-8601>`（格式 `2026-09-20T08:00:00Z`）
- UTC 格式化手写 30 行（era/days-from-civil 标准算法），**不新增 chrono 依赖**（保持单二进制轻量）
- `--version` 与 `version` 子命令输出统一：`memos-cli 0.1.0 (built <BUILD_TIME>)`
- 实现：`#[command(version = concat!(env!("CARGO_PKG_VERSION"), " (built ", env!("BUILD_TIME"), ")"))]`
- 验收：`cargo build` 后 `memos-cli --version` 输出含编译时间；重编译时间戳变化

### P1-4 help 中文化

需求行：`help Print this message or the help of the given subcommand(s) -- 改用中文`

- clap 内置 help 子命令文案是硬编码英文，改为：`#[command(disable_help_subcommand = true)]` + 自定义 `Help` 命令变体

```rust
/// 显示帮助信息（help [子命令]）
Help {
    /// 要查看的子命令名（如 list、+、-、tags）
    #[arg(value_name = "SUBCOMMAND")]
    name: Option<String>,
},
```

- 实现 `cmd_help(name)`：`Cli::command()` → 无参则 `print_help()`；有参则 `find_subcommand(name)` + `print_help()`，未知子命令报 `未知子命令: <name>`
- 子命令中文明细（`list` 等 about 注释）已就位；usage/选项骨架保持 clap 自动渲染
- 注意：`memos-cli help` 与 `memos-cli --help` 输出等价；`memos-cli help +` / `help -` 需能命中（子命令名含符号，clap find_subcommand 支持）

### P1-5 `-tag` 首参省略 list（审计 §3.1，bug 级）

- 现 `run()` 只重写 `+tag`、`/regex/` 首参，漏 `-tag`；实测 `memos-cli -work` 报 `error: unexpected argument '-w' found`
- 重写条件追加：`first.starts_with('-') && !first.starts_with("--") && first.len() > 1 && 首字符非数字（排除 -1 形）`，且命中 P1-2 白名单的 flag 不重写
- 效果：`memos-cli -work` ≡ `memos-cli list -work`

### P1-6 裸词筛选（审计 §3.2）

- `Filter` 新增变体 `Contains(String)`；`Filter::parse` 对无前缀裸词返回 `Some(Contains(word))`，不再 `无法解析筛选`
- 语义 = TW `description.contains:word`：正文子串匹配（与 regex 大小写敏感一致）；多裸词 = AND
- 实测现状 `memos-cli l foo` → `无法解析筛选: foo`（修复目标）
- 边界：`+` / `-` / `/regex/` / `attr:value` 前缀优先解析；数字裸词（`l 2026`）→ contains "2026"
- `parse_filters` 不再对裸词 bail；测试更新（`test_parse_filters_valid_and_invalid` 中 `plain-word` 从报错改为合法）

**Phase 1 验收**：`cargo test` 全绿；实测四例——`memos-cli`（默认 list）、`memos-cli 3`（全文）、`memos-cli -work`、`memos-cli li foo`（contains 筛选）不再报错且输出正确。

## Phase 2：审计吸收（P1 级，用户已同意整体方向）

### P2-1 筛选目标批量删除

- `del` 的 `targets` 支持筛选词（`+tag` / `-tag` / `/regex/` / 裸词 / `time.after:`）：`memos-cli del +draft -y` → 先 `list_all` + `apply_filters` 展开 uid 集合，再与编号/uid 目标合并去重
- 展开用 `list_all`（全量）而非 `page_size`，避免误删范围外的假象/漏删
- `-tag` 与 `-y`/`--force`/`--confirm` 冲突：现有特判先消费已知 flag，非 flag 且 `-` 后非数字 → 排除标签筛选
- 默认确认流程不变（批量删除必须先看预览）；文档化"筛选删除作用于全部匹配"
- Taskwarrior 对应：`task +work delete`

### P2-2 时间筛选 + 智能日期

- `Filter` 新增 `TimeAfter(DateTime)` / `TimeBefore(DateTime)`，匹配 `create_time`（RFC3339，与输出列一致）
- 语法：`time.after:1w`、`time.after:2026-09-01`、`time.before:eom`、`time.before:today`
- 智能日期解析 `parse_smart_date`（新函数，纯 Rust 无依赖）：
  - 相对：`N[d|w|m|y]`（如 `1w`、`3d`、`2mo`）
  - 命名：`now` `today` `yesterday` `tomorrow`；`sow` `som` `soy`（期初）；`eow` `eom` `eoy`（期末）
  - 绝对：`YYYY-MM-DD` / RFC3339
- 边界语义（对齐 TW `due.before`/`due.after`）：`before` 不含时刻（`<`），命名期初/期末的含入含出由边界值决定；文档标注
- 多筛选与 AND 组合自然生效

### P2-3 `tags` 命令（TW `task tags`）

- `memos-cli tags [筛选...]` → `list_all` + `apply_filters` 后聚合 API `tags` 字段，输出 `标签\t命中数`，按命中数降序、同数按字典序
- 别名不设（`tags` 已短；TW 缩写 `ta` 无必要）
- 用途：标签整理、发现拼写变体、配 P2-1 批量清理

### P2-4 `ids` 命令（TW `task ids`/`uuids` 合并简化版）

- `memos-cli ids [筛选...]` → 每行一个 **uid**（不用编号：编号当次列表可变，脚本不可靠）
- 供脚本组合：`memos-cli get "$(memos-cli ids +work | head -1)"`、`for u in $(memos-cli ids /draft/); do ...`
- memos 无删除/完成状态，TW 的 ids/uuids 区分无意义 → 单命令 `ids` 输出稳定 uid

**Phase 2 验收**：`del +tag -y` 只删匹配项；`l time.after:1w` 命中近一条；`tags` 输出可复核；`ids` 输出可直接喂 `get`/`del`。

## Phase 3：纳入实现（P2 级，D4 定稿 2026-09-20）

### P3-1 属性修饰符架构扩展（审计 §3.6）

- 在 P2-2 已建 `attr.op:value` 词法上扩展 `tags.*` / `content.*`：
  - `tags.has:work`（等价 `+work`）、`tags.hasnt:`、`content.startswith:`、`content.endswith:`
- 目的：为未来字段（pinned/archived/visibility）打底；不做完整 TW 修饰符全集（before/after/is… 在 memos 字段语境价值低）

### P3-2 default_filters 常驻筛选（审计 §3.9，TW context 简化版）

- `config.rs` 的 Config 增加 `default_filters: Vec<String>`；配置行 `MEMOS_DEFAULT_FILTERS=+work`（空白分隔，不支持含空格筛选——+tag//regex/ 无空格，够用）
- 应用于 `list`/`tags`/`ids`（读命令）；**不**自动应用于 `del`（危险）；`get` 默认分派不受影响
- 顶层 `--no-default` 跳过；`config --show` 显示该行（脱敏逻辑不涉及）
- 不做 TW 完整 context（read/write 双定义、`context <name>` 切换）——文档依据：审计 §4 曾列 context write 复杂隐射为坑

### P3-3 import 幂等（审计 §3.10）

- `import` 前 `list_all` 收集已存在 uid 集合；逐行 uid 已存在 → 输出 `already exists <uid>` 跳过，否则创建
- 行为：重复导入不产生重复笔记；语法不变
- 失败行仍为 `error ...`；测试补充重复导入用例

## 5. 不采纳项（沿用审计结论，不再实现）

虚拟/特殊标签、delete+purge、undo、隐含 modify、or/xor/() 逻辑、唯一前缀通用缩写（保留硬编码别名）、属性枚举校验、context write、自定义报表列。原因见 `taskwarrior-syntax-audit.md` §4。
